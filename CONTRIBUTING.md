# Contributing to RAWG SDK

We love your input! We want to make contributing to RAWG SDK as easy and transparent as possible.

## Code of Conduct

Be respectful and helpful. We're all here to improve this project together.

## How to Contribute

### Reporting Bugs

Before creating a bug report, check if it already exists. Include:

- **Clear description** of what the bug is
- **Steps to reproduce** the issue
- **Expected behavior** vs actual behavior
- **Screenshots or error logs** if applicable
- **Environment info** (Node version, OS, etc.)

### Suggesting Enhancements

Enhancement suggestions are welcome! Include:

- **Clear description** of the enhancement
- **Use cases** and why it would be useful
- **Possible implementation** ideas

### Pull Requests

1. Fork the repo
2. Create a feature branch (\`git checkout -b feat/amazing-feature\`)
3. Commit changes (\`git commit -m 'feat: add amazing feature'\`)
4. Push to branch (\`git push origin feat/amazing-feature\`)
5. Open a Pull Request

## Development Setup

\`\`\`bash
# Clone repository
git clone https://github.com/SatriaBagusNurhadianto/rawg-sdk.git
cd rawg-sdk

# Install dependencies
npm install

# Run tests
npm run test

# Run linter
npm run lint

# Run type checking
npm run typecheck

# Build project
npm run build
\`\`\`

## Commit Message Guidelines

Follow conventional commits:

- \`feat: add new feature\`
- \`fix: fix a bug\`
- \`docs: update documentation\`
- \`test: add or update tests\`
- \`refactor: refactor code\`
- \`style: format/style changes\`

## Code Style

- Use TypeScript for type safety
- Follow ESLint rules (\`npm run lint\`)
- Write meaningful variable/function names
- Add JSDoc comments for public APIs
- Keep functions small and focused

## Testing Requirements

- Add tests for new features
- Ensure all tests pass (\`npm run test\`)
- Aim for >80% code coverage
- Test edge cases and error scenarios

## Documentation

- Update README.md for user-facing changes
- Update EXAMPLES.md with new usage examples
- Add JSDoc comments to new functions
- Keep documentation up to date

## Pull Request Process

1. Update README.md with any new features
2. Add tests for new functionality
3. Ensure \`npm run test\` passes
4. Ensure \`npm run lint\` passes
5. Ensure \`npm run typecheck\` passes
6. Update CHANGELOG.md

## Questions?

- Create an issue with your question
- Join our discussions
- Email maintainers
